## 既知の問題（2 件）

1. **マスク座標変換が実物のマスク形式に効いていない**
   実物のマスク座標は要素形式（`<crs:FullY>0.4</crs:FullY>`）だが、
   変換処理は属性形式（`crs:FullY="0.4"`）向けの正規表現のため
   変換されない。それにもかかわらず処理ログには「マスク座標変換」と
   記録される。GUI のマスク補正チェックボックスは初期 OFF のため
   実害は限定的だが、ON にした場合は誤解を招く。
   対応案: 要素形式向けの置換を追加する、または変換できた時だけ
   ログに記録する。

2. **マーカー注入が `crs:HasSettings="True"` の存在に依存している**
   この属性が無い XMP では、名前空間宣言だけが入ってマーカー属性が
   入らず、二重適用防止が効かない。Lightroom の通常の書き出しでは
   HasSettings が入る想定だが、より確実な差し込み位置
   （rdf:Description の属性末尾など）への変更が望ましい。

## 未確認事項（実機確認が必要）→ 解決済み（同日夜）

**縦位置写真の Crop 座標軸モデル: センサー（格納）基準で確定**

現行コードは「表示基準」モデル（縦位置では左右が切れる前提）で
計算しているが、実物検証の結果、これは誤りだった。

実物サンプル EM1X9697（縦位置・Orientation = Rotate 270 CW・
Lightroom で手動トリミング済み）で検証した。

- DNG 内の記録: CropTop=0 / CropLeft=0.126482 /
  CropBottom=0.873518 / CropRight=1（格納寸法 3216x2144）
- 編集済み JPG と ORF 埋め込みプレビューを画像照合し、
  表示画面上で実際に切り取られた範囲を実測:
  Left=0 / Top=0 / Right=0.873518 / Bottom=0.873518
  （JPG 画角基準の相対値）
- これは XMP の値を格納空間の値として Orientation 変換した
  結果と一致し、表示基準の読み（左を 12.6% 切る）は
  画像照合で明確に否定された

あわせて判明した関連事項:

- ORF の ImageWidth は全読み出し寸法（5240x3912）であり、
  Camera Raw が使う有効エリア（5184x3888）は Olympus
  メーカーノートの CropWidth/CropHeight にある。現行コードは
  前者を使うため offset に約 0.5% の系統ズレが出る
  （EM1X7734 の実物ペアで end-to-end 実行して確認）
- 縮小版 DNG（OriginalDefaultFinalSize なし、例: 3216x2144）では、
  寸法の絶対値から scale を計算すると誤る。scale は
  格納アスペクト比同士から計算するのが安全

修正依頼は docs/GEMINI_FIX_COORD_SPACE.md と
docs/GEMINI_FIX_ORF_SIZE.md にまとめた。なお、上記の
画角計算テストのうち「縦 3:2」「縦 1:1」の期待値は
表示基準モデル前提だったため、修正後のコードでは
期待値の見直しが必要になる。

同日、ポゴさんがセンサー基準で生成した EM1X9697 用 XMP を
実物 ORF に適用し、クラウド版 Lightroom で目視確認した。
スマホ編集時と同じ切り抜き・画角で再現され、本人から
「最高です」との報告があった。これにより縦位置の座標軸は
ファイル照合と実機表示の両方で確定した。
（撮影は E-M1X + 8mm F1.8 魚眼に広角補正をかける環境のため、
レンズ補正プロファイルの違いによる見た目の差は残るが、
これは本ツールの担当範囲外である。）
