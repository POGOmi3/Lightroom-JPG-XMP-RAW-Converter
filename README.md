# Lightroom JPG XMP → RAW Converter

クラウド版 Lightroom（Lightroom Mobile 含む）で JPG に対して行った
選別・トリミング・簡易現像を、同名の RAW（Olympus .ORF）へ引き継ぐための
Windows 向けデスクトップツールです。

## 何をするツールか

ライブ撮影では RAW（.ORF）＋JPG で記録し、現場では JPG のみをスマホへ
転送して Lightroom で選別・現像し即納しています。帰宅後の本納品で
RAW から現像し直す際、クラウド版 Lightroom には JPG の編集内容を
同名 RAW へ一括同期する機能がありません。

このツールは、クラウド版 Lightroom から「オリジナル＋設定」で書き出した
DNG から編集情報（XMP）を抽出し、RAW 用に書き換えて同名の .ORF の隣に
サイドカーとして配置します。

## 処理の流れ

1. 作業フォルダ（書き出した .dng と未編集の .ORF が入ったフォルダ）を指定
2. ExifTool で .dng から .xmp を抽出（バイナリ抽出、UTF-8 のまま処理）
3. ファイル名末尾の連番（`_6` など）を除去し、同名 .ORF と照合
4. XMP を RAW 用に書き換える
   - JPG / DNG 固有タグの削除（`dc:format`、寸法タグ、Embedded プロファイル等）
   - カメラ内アスペクト比（3:2 / 16:9 / 1:1、縦位置含む）と RAW の
     ネイティブ 4:3 の差を、写真ごとに寸法を測って Crop 座標へ換算・注入
5. オプションで、処理に成功した .dng をごみ箱へ移動

## 「切り抜きが消えた」問題について

原因はタグの破棄ではなく、カメラ内アスペクト比設定と RAW の構造差でした。
3:2 設定で撮った JPG は最初から上下（縦位置では左右）がカットされて
いますが、.ORF は 4:3 の全域を持っています。「切り抜きなし」の XMP を
そのまま RAW に当てると 4:3 全域で展開され、カットされていた部分が
復活します。本ツールはこの差分を Crop として再現します。

## 構成

- `core.py` — 処理本体（GUI 非依存）。抽出・照合・書き換え・安全処理
- `main_gui.py` — PySide6 製 GUI（ドラッグ＆ドロップ、進捗表示、中断）
- `tests/test_core.py` — ExifTool / PySide6 なしで動く単体検証テスト
- `docs/` — 設計・レビュー・検証の記録

## 安全設計

- DNG のごみ箱移動は、抽出成功＋RAW 一致＋書き換え成功の時のみ
- 既存の同名 XMP は `.xmp.bak_日時` の名前でバックアップしてから上書き
- 同じ RAW に対応する DNG が複数ある場合は、処理せず衝突として報告
- 想定外の構造の XMP は、無言で成功にせず「未処理」として報告
- 変換済み XMP にはマーカーを付け、二重変換を防止

## 動作環境・必要なもの

- Windows 10 / 11
- Python 3.11 以降（開発時）、PySide6、send2trash
- ExifTool（`exiftool.exe` と `exiftool_files` フォルダを
  アプリと同じ階層に配置。リポジトリには含めていません）
